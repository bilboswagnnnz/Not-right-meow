# Not Right Meow — QR Quick Link service

This directory contains an optional Cloudflare Worker + D1 relay for **PC displays QR → iPhone scans → player approves → PC gets the same leaderboard identity**. It is **not deployed just by publishing the game's GitHub Pages site**.

## Why it needs a service

GitHub Pages can display the QR image, but cannot relay a phone's approval to a waiting PC. The current leaderboard backend lives at a separate service and cannot be modified from this repository. This tiny Worker provides only short-lived pairing sessions. It does **not** replace the existing leaderboard.

## Setup (one-time)

1. Create a Cloudflare account at https://dash.cloudflare.com/ if needed. In Windows Terminal, make sure Node.js and npm are installed.
2. Open the repository's `pairing-worker` directory in a terminal; run `npx wrangler login`.
3. Run `npx wrangler d1 create not-right-meow-pairing`. Copy its returned database ID.
4. In `wrangler.toml`, replace `REPLACE_WITH_YOUR_D1_DATABASE_ID` with that ID. Keep the existing `ALLOWED_ORIGIN` set to your GitHub Pages origin.
5. Create the table: `npx wrangler d1 execute not-right-meow-pairing --remote --file=./schema.sql`.
6. Deploy: `npx wrangler deploy`.
7. Visit the provided Worker address with `/api/pair/health` appended. You should see `{"ok":true}`.
8. In the game repository, edit `src/pairing-config.js`: change `window.NRM_PAIRING_API = '';` to the full Worker origin (e.g. `https://not-right-meow-pairing.<your-subdomain>.workers.dev`) **without** a trailing slash.
9. Commit that change to `main`. Wait for GitHub Pages to update. The QR feature will then be usable.

After deploying, test on Chrome/Edge PC and Safari on iPhone. Both devices must have an internet connection. Open the game from the **same website origin** on both (for example the GitHub Pages URL, not a downloaded HTML file). Scan the QR with the iPhone camera and accept the request in the same browser where your saved player exists.

## Security and limitations

- Each pairing session uses a random 128-bit ID, a separate 256-bit PC-only claim secret, and a non-extractable ECDH P-256 private key generated by the PC.
- The public key and session ID appear in the QR. **The private PC key, polling secret, and unencrypted recovery token do not.**
- The phone deliberately approves sending the existing browser's player token, encrypted via ECDH/AES-GCM. The relay sees only the ciphertext, stores it briefly in D1, and allows one authenticated pickup.
- Sessions expire in **2 minutes**. The recovery code remains available as a backup.
- Pairing **reuses** the existing leaderboard identity. It does **not** merge two already-created leaderboard identities or remove an older duplicate entry.
- The person controlling your previously paired browser (or its long recovery code) can still submit scores as you. QR linking is not a password-based account system.
- For a public release, monitor abuse and add Cloudflare rate limiting/WAF rules to `/api/pair/start`; cross-origin browser checks alone do not stop scripts.
- The Worker is optional; without its URL configured, clicking Quick Link explains that setup is required. All other game features continue working.

## Browser QA

Run the existing game tests before release, then test:

1. PC without a profile shows QR from the welcome dialog, phone with an established player approves, PC inherits nickname and server personal best.
2. PC with an existing different player asks before switching. Rejecting keeps its old identity. Its former leaderboard entry is not deleted.
3. Wrong browser on iPhone with no player cannot approve.
4. Cancelled, expired, malformed and already-used QR links fail.
5. No link should expose the private recovery code in a QR URL or server logs.
6. Original copy/paste recovery codes still work.
7. Cancel/close while waiting should stop polling and invalidate the pending session.

Run `node --test pairing-worker/test/pairing.test.mjs` from repository root for the worker relay's API logic checks.
